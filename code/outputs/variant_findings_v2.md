# 模型改动对比结果（2026-09-11）

## 一句话结论

把「融合表示真正纳入训练」（`fused` / `gate`）是唯一稳定有效的改动：
**β 读出 CV +0.04、NPMI +0.05~0.07（3 种子中 2 个为正）**，
且对 cTFIDF 读出与跨字段召回**无显著代价**。
按字段长度自动配平重建权重（`autow`）与 per-token 归一化（`token`）**有害**；
排他性正则在数值上**完全无效**。

- 语料：GitHub issues 小规模（1000 训练 / 400 测试，词表 2682）；
  AG News 小规模（同规模，词表 1914）
- K=20，800 epoch，lr=5e-4，线性解码器，20% 验证早停
- 种子：GitHub 11/23/37；AG News 11

- 指标：β / cTFIDF 两种读出的 CV、NPMI、UMass、EXCL_KADJ、IRBO；
  跨字段词预测 recall@10 / precision@10；字段视角 cause/item 一致性

## 两个负面结果（重要，别再花时间）

### 1. 排他性正则在数值上无效

`exclusivity_weight=0.05` 时结果与 base **逐位相同**；加大到 2.0 也只让 CV 变 −0.020。
实测原因：该正则对 β 的梯度比重建梯度小 **约 6 个数量级**
（合成实验：|∂L/∂β| 在权重 0 / 2 / 200 下都是 1.270e+00），
Adam 不会放大小梯度，所以永远不会影响轨迹。
换成按 KADJ 指标定义写的可导近似（行 softmax → 列归一化）同样无效：
权重放大到 1e6 才让梯度变化 0.3%。

→ FC-NTM 的 EXCL_KADJ 只有 0.005~0.008（BTM 0.343、NMF 0.595），
**这是 β 参数化的性质，不是调不调正则的问题**；要改必须改解码器
（例如让解码器直接输出行归一化的主题—词分布），别再调这个权重。

### 2. 按字段长度配平重建权重（autow）与 per-token 归一化（token）都有害

- 公开语料的字段长度是「背景 70.9 词 / 标题 5.2 词」，而 `CAUSE_RECON_WEIGHT=2.0`
  是在私有语料（原因 4 词 / 事项 7 词）上调的，量级完全不同——这个诊断是对的。
- 但按长度把权重配平（标题权重 14.0）之后：β CV −0.051（0/2）、NPMI −0.110（0/2）、
  召回 −0.016，与 prior 组合更是 −0.088 / −0.205。
- per-token 归一化同样明显变差（CV −0.088、NPMI −0.182）。
- AG News 上 autow 的 β CV 反而 +0.113，但 NPMI −0.190、召回 −0.012——一个方向换另一个方向的典型权衡。

→ 结论：**长字段主导重建损失在这两个语料上其实是「有用」的**，
标题字段被 14 倍加权反而破坏了解码器。私有语料调的 2.0 不必改。

## 代码改动清单

`models.py`（`FCNTM`）新增开关，全部默认保持原行为：

| 参数 | 作用 |
|---|---|
| `fusion_mode` | `"mean"` / `"gate"` / `"poe"`，取代原来的 `fusion_gate` 布尔 |
| `missing_prior` | `"zero"`（原行为）/ `"learned"`：缺失字段走可学习先验偏移 |
| `field_weights` | 显式 (cause, item) 重建权重，覆盖 `cause_recon_weight` |
| `recon_norm` / `recon_scale` | `"count"` / `"token"`（逐 token 归一化并整体缩放） |
| `exclusivity_mode` | `"entropy"`（原行为）/ `"kadj"`（按指标定义的可导近似） |

另有两处非开关修复：

1. **一致性正则不再重复前向**：原来为了算 JS 又把两个编码器各跑一遍
   （多一倍编码开销，且混入第二次 dropout 掩码），现在复用主循环已算出的
   μ/logvar。注意：这会改变随机数消耗顺序，单种子结果会漂移 ±0.05，
   不能与 9-10 日记录里的旧数字直接对比。
2. `fused_recon` 路径现在会用两条流的 μ/logvar 构造融合 θ，
   因此 `fusion_mode="gate"` 的 `fusion_logit` 才第一次真正拿到梯度
   （实测从 0.5 学到 0.619）。

新增脚本：

- `run_variant_screen_public.py` — 变体扫描（本次主实验）
- `summarize_variant_public.py` — 汇总 + 配对差值
- `run_variant_queue.ps1` / `run_variant_stagec.ps1` — 串行队列

## 建议

1. **采用 `gate`（或 `fused`）**：β 读出 CV +0.042、NPMI +0.051，无代价。
   它是「融合表示从未训练」这个真实缺陷的最小修复，论文里也讲得通。
2. 论文表 2 的 cTFIDF 行不会因为这件事变好；要提升 cTFIDF 得另找方向。
3. 不要再用 `autow` / `token` / 排他性正则调参。
4. 任何新改动至少跑 3 个种子；本轮的 seed 37 已经证明 1~2 种子会给出相反结论。
